# Java / Kotlin 技术栈约定

- 以仓库声明的 JDK、Maven/Gradle Wrapper 和锁定插件版本为准；优先使用 `./mvnw` 或 `./gradlew`。
- 不绕过已有的模块边界、依赖管理和 Spring 配置约定；新增模块依赖必须更新架构依赖矩阵。
- DTO、领域对象、持久化对象和 API 响应按项目既有边界区分，不为省事跨层复用内部实体。
- 对外输入、配置、消息和持久化数据执行显式校验；异常不得被空 catch 吞掉。
- 新增依赖前检查许可证、维护活跃度、漏洞、传递依赖和 JDK 兼容性。
- 优先执行仓库已有的 Checkstyle/Spotless、Error Prone/编译警告、JUnit 测试及架构测试。
- 数据库迁移必须提供兼容性分析和回滚策略；生产迁移需要人工确认。
