# 约定

## 1. 命名

| 对象 | 规则 | 例 |
|---|---|---|
| 文件 | kebab-case（组件可用 PascalCase） | `user-service.ts` / `UserCard.tsx` |
| 函数/变量 | camelCase | `loadUser` |
| 类型/接口 | PascalCase | `UserProfile` |
| 常量 | UPPER_SNAKE | `MAX_RETRY` |
| 对外接口/通道 | `域:动作` | `user:update` |

## 2. 语言与技术栈规范

本文件只定义跨语言原则，不规定某一种语言的语法偏好。具体语言、框架、格式化器、静态分析器与命令写入 `.spec/stacks/<stack>.md`（项目采用该技术栈时才创建）。

- 启用该语言生态中可用的严格类型/静态分析配置；不能启用时说明原因。
- 外部输入、网络响应、文件内容、消息载荷等边界必须验证；不能把不可信数据直接当作内部模型。
- 错误必须有明确处理策略；忽略异常必须说明可忽略的依据。
- 不把某种语言的习惯（例如 TypeScript 的 `unknown`、`as const` 或 enum 选择）提升为跨语言强制规则。

## 3. 错误处理与用户可见文案

| 场景 | 做法 |
|---|---|
| 可预期失败（未登录、无权限、无额度） | 返回结构化错误，界面提示，不抛异常 |
| 不可恢复（数据损坏、解密失败） | 抛异常，记录，界面给出"下一步该做什么" |
| 后台任务失败 | 不弹窗，写日志 + 内联标记 + 汇总入口 |

**文案纪律**：

- 只说**我们做过的动作**（"已同步"、"已提交"），不说"正常"——那是替用户下判断，错了就是信任崩塌。
- 禁止出现内部术语（`err_code_x`、`state_pending`）直接给用户看，一律翻译成人话。
- 数字必须**一屏内加得起来**；混用多种口径会让用户不知道信哪个。
- 相对时间会失真（"3 天后"渲染一次就固定），关键截止时间给**绝对日期**。

## 4. 提交

格式：`<动词>：<做了什么>（+ 可选一行为什么）`

```
新增：用户导出（支持按标签筛选）
修复：并发写入丢更新（加乐观锁）
重构：把 HTTP 调用抽成 client
文档：补充部署说明
```

- 一次改动一次提交，不混无关修改。
- 提交前跑治理检查与类型检查（pre-commit 已挂）。
- 不 `--amend` 已推送的提交，不 `--no-verify`。

## 5. 测试与验证

| 改动 | 最低验证 |
|---|---|
| 纯函数/工具 | 单元测试或一次性脚本（放 `.tmp/`） |
| 有外部依赖的逻辑 | 本地真实跑一遍，记录实测数字 |
| 界面 | 截图确认，检查文案与对齐 |
| 构建/发布 | 从产物目录启动，确认数据与配置正确 |

**探针脚本一律放 `.tmp/`，验证完删掉。** 禁止把探针留在根目录或提交进 git。
