# 约定

## 1. 命名

| 对象 | 规则 | 例 |
|---|---|---|
| 文件 | kebab-case（组件可用 PascalCase） | `user-service.ts` / `UserCard.tsx` |
| 函数/变量 | camelCase | `loadUser` |
| 类型/接口 | PascalCase | `UserProfile` |
| 常量 | UPPER_SNAKE | `MAX_RETRY` |
| 对外接口/通道 | `域:动作` | `user:update` |

## 2. 语言与技术栈规范

本文件只定义跨语言原则，不规定某一种语言的语法偏好。具体语言、框架、格式化器、静态分析器与命令写入 `.spec/stacks/<stack>.md`（项目采用该技术栈时才创建）。

- 启用该语言生态中可用的严格类型/静态分析配置；不能启用时说明原因。
- 外部输入、网络响应、文件内容、消息载荷等边界必须验证；不能把不可信数据直接当作内部模型。
- 错误必须有明确处理策略；忽略异常必须说明可忽略的依据。
- 不把某种语言的习惯（例如 TypeScript 的 `unknown`、`as const` 或 enum 选择）提升为跨语言强制规则。

## 3. 错误处理与用户可见文案

| 场景 | 做法 |
|---|---|
| 可预期失败（未登录、无权限、无额度） | 返回结构化错误，界面提示，不抛异常 |
| 不可恢复（数据损坏、解密失败） | 抛异常，记录，界面给出"下一步该做什么" |
| 后台任务失败 | 不弹窗，写日志 + 内联标记 + 汇总入口 |

**文案纪律**：

- 只说**我们做过的动作**（"已同步"、"已提交"），不说"正常"——那是替用户下判断，错了就是信任崩塌。
- 禁止出现内部术语（`err_code_x`、`state_pending`）直接给用户看，一律翻译成人话。
- 数字必须**一屏内加得起来**；混用多种口径会让用户不知道信哪个。
- 相对时间会失真（"3 天后"渲染一次就固定），关键截止时间给**绝对日期**。

## 4. 提交

**类型只能从下表选，不要自创**（中文优先；项目已统一用英文就保持英文，别中英混用）：

| 类型 | 何时用 |
|---|---|
| 新增 | 新的对外能力 |
| 修复 | 修 bug（**必须带回归用例**，见 §5） |
| 重构 | 不改行为 |
| 性能 | 只改性能 |
| 测试 | 只改测试 |
| 文档 | 只改文档 |
| 杂务 | 构建、依赖、配置、格式化 |

格式：`<类型>：<改了什么>`，首行 ≤ 50 字，不写句号。

```
修复：并发写入丢更新（加乐观锁）
新增：用户导出（支持按标签筛选）
```

- **一次提交只做一类事**。修 bug 顺带格式化了三个文件 → 拆成两次。混在一起，回滚就没法只回滚一半。
- 首行说"改了什么"，正文说"为什么"。改了什么从 diff 看得见，为什么看不见。
- **修复类提交的正文必须写三样：现象 / 根因 / 怎么验证的。** 缺一样，下次没人知道这条修复防的是什么，很容易被改回去。
- 不 `--amend` 已推送的提交，不 `--no-verify`。钩子拦你就修问题，别绕。

## 5. 测试与验证

| 改动 | 最低验证 |
|---|---|
| 纯函数/工具 | 单元测试或一次性脚本（放 `.tmp/`） |
| 有外部依赖的逻辑 | 本地真实跑一遍，记录实测数字 |
| 界面 | 截图确认，检查文案与对齐 |
| 构建/发布 | 从产物目录启动，确认数据与配置正确 |

**探针脚本一律放 `.tmp/`，验证完删掉。** 禁止把探针留在根目录或提交进 git。

### 修 bug 必须留下一条会失败的测试

**没有回归用例的修复算未完成。** 顺序固定，不许颠倒：

1. **先写用例**：能复现用户报的现象，此时它必须**失败**。跑一遍，把失败输出贴进任务卡 `log.md`。
2. **再改代码**，让这条用例转绿。
3. **再跑全量**，确认没有别的用例被带坏。

第 1 步跳过的话，你只证明了"改完之后没报错"，没证明"修的是用户报的那个问题"。

用例要能被反查：

| 要求 | 例子 |
|---|---|
| 名字说清现象，不写 `test1` | `撤销步必须在写入之前` |
| 注释写清触发条件 | `// 用户报：上传中途点撤销，文件仍被写入` |
| 提交信息引用它 | `修复：撤销步晚于写入（见 upload-safety.test）` |

### 一次修复记三个地方，缺一不可

| 记在哪 | 记什么 | 缺了会怎样 |
|---|---|---|
| 测试文件 | 能自动跑的回归用例 | 下次改动悄悄改回去，没人发现 |
| `.memory/PITFALLS.md` | 根因与以后怎么避开（只增不改结论） | 知道怎么测，不知道为什么这么写 |
| 提交信息正文 | 现象 / 根因 / 验证方式 | 三个月后查不到当时发生了什么 |

### 回归不是跑一次

用例写完要**每次改动都跑**（挂 pre-commit 或 CI）。只跑一次的叫验证，不叫回归。
一条用例如果没人跑，它的价值和没写一样——只是让写的人心里舒服。
