# 宪法 — 红线

> 这些是**不可协商**的技术约束。任何改动违反其一 ⇒ 停下问用户，不要自行权衡。
> 每条都要能回答：「它防的是哪个**已发生过**的具体错误？」答不上来的规则应当删掉。

## 通用（任何项目都适用）

1. **项目外零项目文件写入**。Agent 不得主动在项目目录以外创建、修改或删除项目文件、业务数据与开发产物。工具自动维护的标准缓存和系统临时数据允许存在，但不得擅自修改用户环境。
2. **凭据不落文件**。密钥、token、口令不上传、不打日志、不写明文入库；配置走环境变量或系统凭据库。日志只记键名与状态码。
3. **不做静默失败**。失败必须可见、可定位、可重试；不允许吞错，也不允许用"看起来正常"掩盖未验证状态。
4. **测不了就说测不了**。分母为 0 或未知时记 `N/A`，不得记 `0%`；未覆盖的场景标 `unverified`，不计入"通过"。
5. **批量写入必须有恢复边界**。多文件变更优先使用事务式暂存、失败回滚和写后校验；必须说明回滚覆盖范围与无法覆盖的中断情形。不得把尽力回滚描述成断电/强制终止下的原子事务，也不得承诺未经验证的“一键回退”。
6. **根目录白名单**。新增根级目录/文件必须先进 `gov.toml [dirs]`；临时产物只进 `.tmp/`，构建产物只进 `{{BUILD_OUTPUT}}/`。
7. **单一规则入口 + 分域事实源**。规则入口为 `AGENTS.md`；意图 `.spec/intent/`、需求 `.spec/requirements/`、验证 `.spec/verification/` 与跨会话断点/稳定事实 `.memory/` 始终保留各自权威来源；仅在启用 `task_tracking` 时，任务状态以 `.spec/tasks/index.md` 为准；仅在启用 `roadmap` 时，里程碑状态以 `.spec/roadmap/INDEX.md` 为准；仅在启用 `adr` 时，架构决策以 `.spec/adr/` 为准。关闭可选能力不删除历史记录，也不要求新建对应记录。客户端私有记忆只能作缓存，不得成为权威来源。
8. **契约单向依赖**。外层（UI/CLI/API 层）不得直接引用内层实现细节，只能通过显式接口通信。
9. **不引入无出处的常量**。阈值、超时、重试次数必须写清来源（实测/规范/用户给定），否则标为「待校准」。

## Agent 操作权限

| 操作 | 默认权限 | 要求 |
|---|---|---|
| 读取仓库文件、运行只读查询 | 自主 | 遵守敏感信息边界 |
| 修改任务范围内代码 | 自主 | 启用 `task_tracking` 时以任务卡 scope 为准；关闭时以用户当次指令为准，完成后执行对应验证 |
| 修改项目已启用的治理索引、记忆和执行日志 | 自主 | 仅维护当前项目实际启用且存在的治理资产，遵守文件所有权与生命周期规则 |
| 新增第三方依赖 | 先评估 | 说明用途、替代方案、维护与安全影响；启用 `adr` 时记录架构取舍，关闭时更新 `.spec/01-architecture.md` 或 PR 审查记录 |
| 修改数据库结构 / 迁移脚本 | 先给方案 | 说明兼容性、回滚路径与数据风险；生产迁移必须人工确认 |
| 批量删除、重命名大量文件 | 人工确认 | 先列出影响范围与恢复方式 |
| 修改 Git 历史、强制推送 | 人工确认 | 不得改写他人已基于其开展工作的历史 |
| Git Push、创建 Release、部署生产 | 人工确认 | 明确目标、变更内容与回滚方案 |
| 修改 AGENTS、宪法、治理脚本或规则预算 | 人工确认 | 说明原因、影响和回归测试结果 |
| 修改用户级系统配置、终止用户进程 | 人工确认 | 不得擅自改变宿主环境 |

**权限原则**：不可逆、外部可见或影响用户数据的操作必须由用户明确授权；任务卡 scope 不覆盖这些权限。任务卡仅在启用 `task_tracking` 时作为代码范围依据。

## 项目特有（按实际替换）

> 下面几条是从真实项目带过来的示例，**请按本项目改写或删除**。

10. **不改用户环境**。迁移或切换配置时不得顺手改变设备标识、路径、时区等隐含状态——环境突变本身就是风险信号。
11. **未经明确确认，不终止用户正在使用的进程**。允许"经用户点确认后关闭"，不允许后台偷偷杀。
12. **区分「我们造成的」与「外部造成的」**。自己的操作引发的失败必须与外部原因分开计数，否则会去优化一个不存在的问题。

---

## 违反时怎么办

- 若某条红线**阻止你解决真实问题** ⇒ 停下并取得用户裁定；启用 `adr` 时在 `.spec/adr/` 留下决策记录，关闭时在 `.spec/01-architecture.md` 或 PR 审查记录中保存冲突、裁定和依据。无论哪种情况，都不得自行越过红线。
- 裁定通过后：先改本文件与 `AGENTS.md`，再改代码。**顺序不能反**。
