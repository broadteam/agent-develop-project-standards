# 判据与实证（只增不改结论）

> 每条都是**真实踩过**的，不是想象中的风险。新坑追加到末尾，编号不复用。
> 格式：现象 → 根因 → 对策。写不清根因的，说明还没定位，别急着记。

## 环境与工具

- **P1 删除命令可能被安全垫片拦截**。某些环境会把 `rm` / `Remove-Item` 接管为"先送回收站"，目标过大或文件被占用时回收站失败，于是**拒绝降级为永久删除**。表现为"删不掉"，实际是保护机制在拦。对策：先释放占用，再删；确需强删时由用户手动操作，不要用其他命令绕过。
- **P2 目录被当前进程占用时无法重命名或删除**（`Device or resource busy`）。对策：先把工作目录切走，或关掉占用它的应用。
- **P3 网络路径（UNC / 挂载盘）上写入可能失败**。只读浏览通常没问题，写入改用本地路径或脚本重定向。

## 版本控制

- **P4 换行符会毁掉 shell 脚本**。Windows 上 `core.autocrlf` 把 `.sh` 转成 CRLF 后，shebang 变成 `#!/bin/sh\r`，报 "required file not found"。对策：`.gitattributes` 里对 `*.sh` 固定 `eol=lf`。
- **P5 文件模式位丢失**。跨文件系统拷贝后脚本失去可执行位，`git add` 会记成 644。对策：`git update-index --chmod=+x <file>`，并 `git config core.fileMode false`。

## 依赖与构建

- **P6 构建产物散落是灾难**。每次迭代留一份 `out2`/`out8`，几轮就占几个 G，且不知道哪份是最新。对策：产物只留一个目录，旧包归档到项目外，并在治理检查里禁用序号目录。
- **P7 改包名/应用标识会改变用户数据目录**。改名后老用户看到"数据全没了"（其实在旧目录）。对策：改名必须带迁移逻辑，且迁移要幂等、失败可回滚。
- **P8 原生模块不能从打包归档里加载**。需要显式解包配置，否则启动即崩。

## 改代码的代码（用脚本批量改文件）

- **P11 字符串替换只匹配了一半表达式，把链式调用改断了**。实测：想把 `.join([...].map(x => `${x}/`).join('\n'))` 换成 `.join(profile.ignore.join('\n'))`，替换串漏了开头的 `.join(`，结果变成 `.split(...)` 后直接跟表达式，语法错误。**对策**：① 替换前先打印原文那一行，确认匹配边界；② 改完立刻 `node --check` / `python -m py_compile`；③ 一次只改一处，别在一个脚本里改五个地方。

## 规范与工具本身

- **P12 覆盖钩子会导致检查静默降级**。实测：把项目原有的 `pre-commit`（跑治理检查 + 类型检查）直接替换成模板版本（只有治理检查），提交照样"通过"，但类型错误已经能混进去了。**比没有钩子更危险**——人以为有保护。对策：换钩子前先看原有内容，把项目特有的检查追加到模板钩子末尾。

## 协作与流程

- **P9 「看起来正常」比报错更危险**。未验证的状态被显示成"正常"，用户会基于错误信息做决定。对策：不确定就标"未验证"。
- **P10 一屏内数字混用多种口径**。用户会问"到底信哪个"。对策：结论行的数字必须互斥且加总等于总数，时间窗增量降为小字。
