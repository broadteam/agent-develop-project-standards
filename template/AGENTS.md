## 0. 不可协商四条

1. **项目内自足**。只读写本项目目录；**禁止**主动在项目外创建、修改或删除项目文件、业务数据与开发产物。工具运行所需的标准缓存（如 Maven/Gradle/npm/Python 缓存）和系统临时数据允许由工具自动维护，但不得擅自修改用户环境。
   唯一例外：产品运行时写自己的用户数据目录——那是产品数据，不是开发产物。
2. **根目录白名单**。根目录只允许 `gov.toml [dirs]` 列出的目录/文件；临时产物只能进 `.tmp/<任务ID>/`，构建产物只能进 `{{BUILD_OUTPUT}}/`。
   **禁止** `out2` `test1` `tmp` `新建文件夹` 这类序号/随手目录。
3. **单一入口 + 单一记忆**。规则看本文件，状态看 `.memory/MEMORY.md`。
   **禁止**任何 agent 将私有 memory 或 rules 文件作为项目状态、任务进度、架构决策的权威来源。
4. **一次改动一次提交**。提交信息写清"动了什么 + 为什么"。

## 0.5 会话协议（按任务分级）

**每次会话的最小开工动作**：
1. 读取本文件。
2. 读取 `.memory/MEMORY.md` 的 §0 断点。
3. 仅在需要判断项目治理能力、技术栈或验证命令时，读取 `project-profile.toml` 的相关字段；画像为 `needs_review` 时，不得把候选值当成已确认事实。
4. 判断本次工作属于「轻量任务」还是「跟踪任务」，再按下表读取额外材料。

不要把「读过所有规范」当成开工条件。只读当前任务会用到的内容；读过的文件在本次会话中不必重复读取。

### 任务分级

| 类型 | 判定 | 工作方式 |
|---|---|---|
| **轻量任务** | 单点、局部、验收明确；不改变架构、模块边界、数据结构、对外契约、权限或依赖 | 用户当次指令就是范围；无需为了形式创建任务卡。完成相关验证即可 |
| **跟踪任务** | 跨多个模块/文件、预计跨会话、需求或验收不确定，或涉及架构、数据迁移、公共契约、安全边界、依赖变更 | 先读任务索引，再读或创建对应任务卡；按卡片 scope 推进 |
| **高风险操作** | 生产数据/环境、部署、外部可见操作、批量删除、Git 历史改写等 | 无论任务大小，按宪法权限表先取得明确授权 |

任务分级按**影响与不确定性**判断，不按文件数量机械判断。轻量任务一旦发现范围扩大或风险上升，立即转为跟踪任务；不必为了保持原分类而继续推进。

### 开工时按需读取

| 材料 | 读取时机 |
|---|---|
| `.spec/00-constitution.md` | 涉及权限、数据、安全、架构红线或高风险操作时；不要求每个轻量任务重复通读 |
| `.spec/tasks/index.md` + 对应 `card.md` | 跟踪任务；轻量任务无需强制建卡 |
| `.spec/intent/BASELINE.md` + `CHANGES.md` | 跟踪任务、跨会话恢复、需求/计划变更或阶段回顾时 |
| `.spec/roadmap/INDEX.md` + 里程碑详情 | 任务属于某个里程碑，或需要调整阶段计划时 |
| `.memory/PITFALLS.md` | 当前问题涉及其中某个领域，或正在排查已知故障模式时；按主题定位，不要求每次通读 |
| `.spec/adr/` | 需要理解或挑战相关架构决策时；只读相关 ADR |
| `git log` / `git show` | 断点引用了提交、排查回归/历史行为、或当前实现意图不清时；不是每次会话的固定步骤 |

**收口要求**：
- 跟踪任务按卡片完成开工/收口对齐；`unresolved_drift` 不得 done。里程碑关闭前核对目标判据与 R/V 证据（详见 CHANGES）。
- 轻量任务：只有产生了后续会话必须知道的事实、决策或未完成事项时，才更新记忆/日志；不要为了留痕重复抄写代码 diff。
- 新增的跨会话规则进入 `.memory/MEMORY.md`；可复现的判据级教训进入 `.memory/PITFALLS.md`。
- **客户端私有记忆只是缓存**（如 `.workbuddy-ai/`、各客户端自己的会话记忆）：项目级事实必须写回 `.memory/`，只留在私有目录等于没记。开工读 `.memory/MEMORY.md` §0，不读私有记忆当权威。
- 任何验证都如实记录：未执行标记 `unverified`，不得写成通过。

**规则阻碍真实工作时**：不要绕过检查或默默违反规则。说明冲突与影响；涉及宪法级约束时按 ADR 流程提交用户裁定。普通流程规则可提出最小修订，不需要先把问题升级成架构决策。

## 2.6 分级读取（按需，不是强制清单）

| 级 | 内容 | 读取规则 |
|---|---|---|
| **L0 会话基线** | `AGENTS.md` + `.memory/MEMORY.md` §0 | 每次会话读取；只读断点，不要求加载整份记忆 |
| **L1 任务索引** | `.spec/tasks/index.md`、`.spec/roadmap/INDEX.md` | 仅跟踪任务或阶段规划需要时读取 |
| **L2 单点详情** | 命中的 `card.md` / `milestone.md` / ADR / 技术栈文件 | 只读当前任务相关条目 |
| **L3 历史归档** | `archive/`、历史日志、旧方案 | 默认不读；只有追溯问题或核实历史决策时按需读取 |

### 使用规则

1. **从当前问题出发**：先确定要解决什么，再读取能回答它的最少文件。
2. **先索引，后详情**：需要查看任务或里程碑时，先读索引，再读命中的单项。
3. **信息不足时扩展读取**：最少上下文无法解释实现、风险或失败原因时，继续读取相关源码、测试、历史记录；不能为了省 Token 猜测。
4. **超预算先压缩，不删事实**：优先去重、归档过期内容；不得删除仍影响正确性或安全性的必要事实。

`node .standards/check-governance.cjs` 检查根目录。允许的目录与文件以 `gov.toml [dirs]` 为**唯一来源**，本文件不重复列举——重复的清单会随每次重跑变长，且两处必然走样。

## 5. 快速命令

```bash
{{COMMANDS}}

# 治理检查
node .standards/check-governance.cjs

# 一次性启用提交闸门（每个新克隆都要执行）
git config core.hooksPath .githooks
```

**pre-commit 钩子**会跑治理检查，不通过直接拦下。确属误判时改 `gov.toml [dirs]`，不要用 `--no-verify` 绕。

**通用 Hook 与项目检查分离**：项目专属检查写入 `.githooks/pre-commit.local`，不要直接修改通用 `pre-commit`。
模板不知道你项目的类型检查 / lint / 测试命令，所以 `pre-commit` 默认只跑治理检查。
铺完之后复制 `.githooks/pre-commit.local.example` 为 `.githooks/pre-commit.local`，启用本项目检查：

```sh
cp .githooks/pre-commit.local.example .githooks/pre-commit.local
# 编辑 pre-commit.local，取消注释并替换成项目真实命令
```

**模板不会声称项目测试已通过**：未配置的项目检查不会被假装执行。每个项目应在钩子或 CI 中明确配置构建、lint、类型检查和测试命令。
